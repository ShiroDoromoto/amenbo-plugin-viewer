# amenbo-plugin-viewer

PC から離れているあいだも、スマートフォンから [**amenbo**](https://github.com/ShiroDoromoto/amenbo)
のタスクの進み具合を見る。**amenbo Viewer** の実装。

amenbo 本体は外部と通信しない。運営もデータをホスティングしない。**置き場は利用者が持つもの**で、
そこへレコードを片方向に運ぶ。**運ぶのは動いたぶんだけ**で、電話は自分が読んだ点から先を取る。

## 何が入っているか

| 部品 | 動く場所 |
|---|---|
| プラグイン | 利用者の PC（Windows / macOS / Linux） |
| Worker | 利用者の Cloudflare |
| iOS アプリ | iPhone |
| Android アプリ | Android 端末 |

4つは同じ契約（レコードの形・暗号の封筒・QR に載せるもの・エンドポイントの仕様）を共有する。
**契約が変わると4つとも変わる**ので、1つのリポジトリに置いてある。

## 構成

部品ごとにディレクトリを分ける。それぞれ別のツールチェーンを持つので、リポジトリ直下は
どの部品にも渡さない。

| | 中身 |
|---|---|
| [`plugin/`](plugin/) | プラグイン（Go） |
| [`worker/`](worker/) | Cloudflare Worker |
| [`app/`](app/) | スマートフォンアプリ（Flutter。`ios/` と `android/` はこの下に生成される） |

**契約を散文で置く場所は作らない。** 置けば、どの部品を直しても文書の追従が要り、
その漏れは静かに起きる——3つとも動いていて文書だけが嘘、という形になる。
契約は動くものの側に持たせてある: 経路は Worker のルート表、レコードの形は送る側と取り込む側の
コード、封筒は両側のコードと、両方を通しで踏む検証。**ずれは読んで見つけるのではなく、通して見つける。**

ビルドはルートの `Makefile` が束ねるだけで、実体は各部品の `Makefile` が持つ。

```
make plugin   # その部品だけ（worker / app も同じ）
make build    # 3部品まとめて
```

## 経路は2つ

| 利用者 | 経路 | 利用者の手数 |
|---|---|---|
| **mac ＋ iPhone** | **アプリ専用の iCloud コンテナ**（基本） | **ゼロ**（選ぶフォルダも無い） |
| それ以外の組み合わせ | 利用者自身の Cloudflare Worker ＋ D1（救済） | Cloudflare のアカウント1つ（立てるのはプラグイン） |

置き場が違うだけで、運ぶ物・一方通行・**レコード1件ずつという単位**は共通である。

**封をするかどうかは置き場で違う。** Cloudflare は利用者が借りている場所なので暗号文しか置かない。
iCloud のフォルダは利用者自身の端末とアカウントなので、手元の DB と同じく行のまま置く——
鍵を要求すると、鍵が生まれるのは Worker を立てる工程なので、**mac だけの人が通れなくなる**。

置き場が D1 なのは、**1キーの上書きでは答えられないことが2つある**ため——
「この順番から先で何が変わったか」と「この行を忘れろ」。だから電話が読むのは範囲で、
PC が送るのは動いた行だけになる。
