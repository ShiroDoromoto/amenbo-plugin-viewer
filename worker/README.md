# worker — Cloudflare Worker

利用者自身の Cloudflare アカウントに立てる。運営側は何もホスティングしない。
プラグインがセットアップを手伝い、立てたあとの持ち主は利用者になる。

中身は解釈しない。受け取るのは「PC が付けた鍵」と「PC が封じたバイト列」だけ。

認証はセットアップ時に生成する長いランダムトークン。アカウントもパスワードも作らない。
鍵は渡らないので、Cloudflare が見るのは暗号文だけになる。

| 応答 | |
|---|---|
| `401` | トークンが無い・知らない。経路の判定より先に立てているので、通っていない相手には経路も見えない |
| `403` | トークンの種類が違う（読み取り用で書こうとした、など） |
| `404` / `405` | 経路が無い／そのメソッドは取らない（`Allow` を返す） |
| `400` | 本文が受け取れる形になっていない |
| `409` | 既にある名前へ読み取りトークンを発行しようとした／端末のカーソルが並び順の先を指している（→「並び順は巻き戻らない」） |
| `413` | 1回の書き込みが受ける件数を超えた |
| `503` | Secret が入っていない |
| `507` | 置き場が一杯で、これ以上は入らない |

## トークンは2種類

書くのは PC、読むのは端末。同じものを持たせない。

| | 置き場所 | できること |
|---|---|---|
| 書き込みトークン | この Worker の Secret（`WRITE_TOKEN`）、1本 | `PUT` と `DELETE` |
| 読み取りトークン | `tokens` の1行、**ハッシュだけ** | `GET` |

**眼目は端末1台だけを切れること。** 1本を共有すると、1台失くしただけで全端末が再ペアリングになる。

| 口 | |
|---|---|
| `PUT /tokens` | `{"label":…,"hash":…}` を受けて1本足す。**トークンの値は届かない**。既にあるラベルは `409` |
| `DELETE /tokens/<ラベル>` | その1本を切る。無いラベルは `404`——打ち間違いを「切れた」と答えない |

- ハッシュは **SHA-256 を小文字16進64桁**。作るのは PC で、この Worker は照合しかしない
- **既にあるラベルへの発行は断る。** 上書きすると、そのラベルの端末は黙って読めなくなる——
  名前を打ち間違えただけで、触るつもりの無かった端末が止まる。同じ端末を繋ぎ直すなら**切ってから出し直す**
- 書き込みトークンの比較は定数時間。読み取りは**ハッシュでの照合**なので定数時間にしていない——
  漏れうるのはハッシュで、それを知っても通れない

## 置き場は D1

**レコード1件が1行。** 1キーの上書きでは、この置き場が訊かれる2つのこと——
「この順番から先で何が変わったか」「この行を忘れろ」——のどちらにも答えられない。
だから端末が読むのは範囲で、PC が送るのは動いた行だけになる。

| 表 | 中身 |
|---|---|
| `records` | 鍵・順番（`seq`）・操作（`put` / `del`）・nonce・暗号文 |
| `tokens` | ラベル・読み取りトークンの**ハッシュ**・発行日 |
| `store` | 台帳の版・**並び順の現在地**・最終更新（1行だけ） |

- **削除は行として残す。** 消えた行にすると、離れていた端末は「消えた」ことを知る機会を失う
- `seq` は一意。同じ順番に2行あるとページの境目が定まらず、端末が飛ばすか二重に読む
- **トークンの値は置かない。** 照合しかしないので、置けば全端末ぶんが一度に漏れる面が増えるだけ

### 一杯になったら `507`

置き場の広さは D1 の上限で決まる——無料プランで 500 MB、有料で 10 GB。届いたら書き込みを `507` で断り、
一杯であることと、アカウントを上げれば広がることを文で返す。残量は見せないので、
利用者がそれを知るのは詰まった瞬間になる。だから断りの文が次の一手まで届いていないと、そこで手が止まる。

**全部が止まるわけではない。** 読み取りと `DELETE /tokens/<ラベル>` は一杯でも通る。
**`PUT /reset` も通る**——記録を空にしてから置き直す口なので、立て直しはいちばん要るときに使える。

## レコードの口

| 口 | |
|---|---|
| `PUT /records` | 動いたレコードを置く。削除も受ける。答えは `{"seq":…}`——置き場の現在地 |
| `GET /records?since=<seq>` | その並び順より後を、ページに割って返す |
| `GET /meta` | 版・現在地・最終更新。**取りに行く前に訊く安いほう** |
| `PUT /reset` | 置き場を空にしてから全量を受ける |

```json
PUT /records
{"spec_v":1,"version":12345,"records":[
  {"k":"task/2812","op":"put","n":"<nonce>","c":"<暗号文>"},
  {"k":"task/2799","op":"del"}
]}
```

- **中身は解釈しない。** `k` は PC が付けた文字列、封筒は開けられないバイト列で、形だけを見て通す
- **1回の書き込みは 500 件まで**。超えたら `413` と「分けて送れ」の一文を返す。
  データベースの中で失敗させると、送り手には「通らなかった」以外の情報が残らない
- **読みは 200 件で1ページ。** `more` が次があることを言い、`seq` がそのページの到達点になる。
  端末は「ページを書く → 次を訊く」を繰り返すので、1週間離れていた端末も1分の端末も同じ作りで済む
- `version` は台帳そのものの版。**同じ版がもう一度来たら `PUT /records` は何もしない**——
  答えを聞き逃した送り手の再送で、全レコードが並び順の先頭へ動くのを避ける。
  `PUT /reset` は立て直しの口なので、版が同じでも必ず働く

### 並び順は巻き戻らない

`seq` は `records` の最大値ではなく **`store` の1行**に持たせてある。リセットは `records` を空にするので、
行から数え直す作りだと**次のリセットで番号が振り直しになる**。振り直した番号は、リセット前のカーソルを
持ったままの端末にとって別のレコードを指すので、端末は取り違えたまま気づけない。

だから並び順は置き場の一生を通して増え続け、リセットもその続きから番号を振る。
そのうえで、**現在地より先を指すカーソルは `409` で拒む**——巻き戻らない以上「先」はありえず、
それは別の置き場で数えたカーソルなので、最初から読み直させる。

`wrangler.jsonc` に `database_id` を書いていないのは、この Worker が利用者のアカウントへ入るため。
デプロイはその場でデータベースを作り、プラグインは同じ枠を API で埋める。

## 動かす

```
npm ci
npm run typegen    # wrangler.jsonc から Env の型を出す
npm test           # workerd の中で走らせる。移行はテストが自分で当てる
npm run check      # typegen → tsc → deploy --dry-run
npm run dev        # ローカル。.dev.vars.example を .dev.vars に写す
```

表の変更は `migrations/` へ足す。テストは**デプロイが当てるのと同じ移行**を読んで当てるので、
通らない移行は誰かのアカウントではなくここで落ちる。

`npm run deploy` は手で触るとき用。ルートの `Makefile` からは届かない位置に置いてある。

CI（[`.github/workflows/worker.yml`](../.github/workflows/worker.yml)）が回すのは `make build` と
`make test` の2行だけ。**段を向こう側だけに足さない**——足した瞬間、手元が全部緑でも push すると
赤くなる形ができる。`deploy --dry-run` は組めるかを見るだけなので、資格情報は要らないし置いていない。

## プラグインが焼き込んで運ぶ

利用者のアカウントへ立てるのはプラグインで、利用者の PC に Node は無い。だから
**ここをビルドしたものがプラグインのバイナリに入る**。`make build` も `make test` も
`plugin/worker.js`（esbuild が吐いた本体）と `plugin/schema.sql`（`migrations/` を連ねたもの）を
焼き直すので、`src/` や `migrations/` を触ったら**一緒にコミットする**。

**この2つは生成物。手で書き換えない。**
