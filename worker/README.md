# worker — Cloudflare Worker

利用者自身の Cloudflare アカウントに立てる。運営側は何もホスティングしない。
プラグインがセットアップを手伝い、立てたあとの持ち主は利用者になる。

エンドポイントは3つだけで、中身を解釈しない。

| | |
|---|---|
| `PUT /snapshot` | 暗号文を受け取り KV へ置く。キーは毎回同じ。版番号が前の版以下なら拒む |
| `GET /snapshot` | 暗号文を返す |
| `GET /meta` | 版番号と更新時刻。本体を落とす前に「新しいものがあるか」を訊く |

認証はセットアップ時に生成する長いランダムトークン1本。アカウントもパスワードも作らない。
鍵は渡らないので、Cloudflare が見るのは暗号文だけになる。

| 応答 | |
|---|---|
| `401` | トークンが無い・違う。経路の判定より先に立てているので、通っていない相手には経路も見えない |
| `404` / `405` | 経路が無い／そのメソッドは取らない（`Allow` を返す） |
| `503` | Secret が入っていない |

## KV は1キーの上書き

新しいキー名で置くと、KV が不在もキャッシュするため端末は最大60秒 404 を見る。
上書きなら古い版が見える。列挙も走査もしないので、名前空間1つ・キー1つで足りる。

`wrangler.jsonc` に `id` を書いていないのは、この Worker が利用者のアカウントへ入るため。
`wrangler deploy` はその場で名前空間を作り、プラグインは同じ枠を API で埋める。

## 動かす

```
npm ci
npm run typegen    # wrangler.jsonc から Env の型を出す
npm test           # workerd の中で走らせる
npm run check      # typegen → tsc → deploy --dry-run
npm run dev        # ローカル。.dev.vars.example を .dev.vars に写す
```

`npm run deploy` は手で触るとき用。ルートの `Makefile` からは届かない位置に置いてある。
