# app — amenbo Viewer（Flutter）

iOS と Android を1本で作る。`ios/` と `android/` は Flutter がこの下に生成する。

| | 値 |
|---|---|
| ストア表示名 | amenbo Viewer |
| バンドル ID / パッケージ名 | `work.amenbo.viewer` |
| Dart のパッケージ名 | `amenbo_viewer` |

表示名は日英どちらでも通るので、言語ごとに変えず揃える。

iOS は2経路を持つ。アプリ専用の iCloud コンテナ（`iCloud.work.amenbo.viewer`）を読む経路と、
Cloudflare へ HTTPS で取りに行く経路。Android は Cloudflare 経路だけ。
復号した後の扱いはどちらも同じで、書き戻さない。

**iCloud 経路に、この端末の操作は無い。** 利用者はフォルダを選ばない——置き場はエンタイトルメントで
与えられ、コンテナの `Documents/` を直に読む（`ios/Runner/ICloudContainerBridge.swift`）。
そのディレクトリを作れるのはアプリだけなので、**mac 側の書き先はアプリを一度起動して初めて生える**。
iCloud にサインインしていない状態は失敗ではなく、`available: false` として扱う。

## 見た目の作法

画面ごとに決めるとばらつくものを、テーマと共通ウィジェットに落としてある（`lib/ui/`）。

- **Material 3 を1セットで両 OS に出す。** 色は teal のまま。プラットフォームで見た目を変えない
- **大きさを自分で書かない。** 文字は OS の設定に従う。表題は2行で止める（`RowTitle`）
- **状態を色だけで表さない。** 優先度・期限切れ・状態は、かたちと語を併せる（`marks.dart`）
- **行は1つの塊で読み上げる。** `rowLabel` が文を作り、`SpokenAsOne` が中の記号を黙らせる
- **時刻は相対。** 絶対時刻は長押しで出す（`TimeOnHold`）
- **触覚は2回だけ**——引き下げた更新の反映と、初回同期の完了。**音は鳴らさない**（`touch.dart`）
- **幅があれば2面**（`TwoPane`）。判定は幅で、端末の種類では決めない
- **番号は押せばコピー**（`RefChip`）。書き戻せないので、PC へ渡す橋がここになる
- **行は共通の1つ**（`task_row.dart`）。2行で止め、**本文の抜粋は出さない**。2行目に入りきらないときに
  削るのはプロジェクト名の側で、止まっている理由と期限は削らない
- **本文の Markdown は自前**（`markdown.dart`）。描くのはバックログが実際に使う範囲だけで、
  **mermaid はソースのまま**・**画像は取りに行かず枠と URL**・**`##` の節は畳める**（最初の1つだけ開く）。
  範囲外の記法は書かれた文字のまま出す

**文言は英語1本。** 翻訳の仕組みを持たない——読み手は自分のバックログを読む人で、
語彙はそのバックログの側にある。

**リストの並べ替えをアニメーションで見せない。** 読んでいる場所が飛ぶ。並びが変わる面では
`AnimatedList` を使わない。

## 手元の持ち方

復号した像は **SQLite に行のまま置き、画面はそこへ問い合わせた結果だけを持つ**（`lib/store/`）。
全件を配列に読んでから絞る形にしない——バックログは消さずに積むもので上限が無く、iOS は
メモリ圧で背面のアプリを落とすので、抱えるほど前面復帰のたびに作り直すことになる。

| 面 | 一度に持つ量 |
|---|---|
| 一覧の各束 | 先頭20件 |
| リストの面（さがす・束の続き・分類の値・前回以降） | 50件ずつ |
| タスク詳細のコメント | 最新3件から20件ずつ遡る |
| 総数 | 999 で数えるのをやめる |

置き方は2段になっている。**届いた行はそのまま `record` に置き**（契約の `テーブル名/行 id` がそのまま鍵）、
並べ替えと絞り込みに要る短い列だけを別の表へ写す。長い本文が1か所にしか無いので写しは安く、
表の形を変えても**手元の行から作り直せる**——アプリの更新のたびに再ダウンロードさせない。

検索は FTS5 の索引に任せる。トークナイザは **trigram**——日本語には語を切る空白が無い。
3文字に満たない語だけは索引が答えられないので `LIKE` に落ちる（`QR` のような語が実際に打たれる）。

SQLite は **`sqlite3` パッケージが同梱するものを使う**（OS のものを呼ばない）。端末・手元・CI で
同じ版が動き、FTS5 と trigram が在ることを版の当たり外れに任せずに済む。

iOS では DB に `NSFileProtectionComplete` を付け、**ロック中は読めなくする**（`ios/Runner/FileProtectionBridge.swift`）。
読むのは起動時と前面復帰時だけなので、ロック中に読めなくても困らない。Android に相当するものは無い——
アプリ専用の領域に置き、端末の暗号化に委ねる。**守る対象は鍵1つに絞る**（本文は平文で置く）。

## ペアリング

Cloudflare 経路の設定はこれ1つきりで、**PC の画面に出た QR をカメラで読む**だけ（`lib/pairing_scan.dart`）。
載っているのは版・URL・この端末の読み取りトークン・暗号鍵で、読み替えは `lib/pairing_code.dart` が持つ。

- **カメラを求める前に理由を1行出す。** 断りなく出た OS の確認は反射で答えられ、「いいえ」は
  この端末で唯一の設定作業を1タップで塞ぐ
- **読めた瞬間に保存して閉じる。** 確認のボタンは挟まない——読み直しはいつでも効くので、
  挟んだところで利用者に base64 を検分させるだけになる
- **断られても終わりにしない。** 設定アプリへの導線と、PC の画面を撮った写真から読む道を出す。
  後者は権限を1つも要らない
- **版は他の3つより先に確かめる。** 先の契約はフィールドを動かしているかもしれないので、
  「URL が無い」は正しい問いへの誤った答えになる
- **合う合わないだけを言わない。** 別のアプリの QR・新しい版・長さの違う鍵は、それぞれ次の手が違う
- **http の置き場は受けない。** 載っているトークンはこの端末の入場券で、平文で送れば端末のものでなくなる
- **鍵はここで一度開いてみる。** 長さの違う鍵は最初の同期でも同じように失敗するが、
  画面に向けている今なら利用者に打つ手がある

カメラ・権限・写真の3つのパッケージは**この画面だけのもの**で、以後どこからも呼ばれない。

## 取り込み

**通信するのはここだけ**（`lib/cloudflare_intake.dart`）。画面はローカルの DB しか読まない。
置き場の並び順は増える一方で、端末は自分が読んだ点を覚えている——だから1周は
「`GET /meta` でどこまで来ているかを訊く」「先に居るなら、その先をページごとに取る」の2つで終わる。

- **1ページ開いたらその場で書く。** 全量を組み立ててから保存すると、初回同期という
  いちばん落とされやすい瞬間に、開いたぶんを丸ごと捨てることになる。ページ単位なら
  中断の代償はそのページだけで、カーソルは入ったぶんまで進んでいる
- **版はページが尽きてから採る。** `more` が続くあいだは半周ぶんしか持っていないので、
  そこで版を書くと「最新に追いついた」と嘘をつく
- **開かないレコードは飛ばさない。** 置き場へ書ける相手はレコードを別の名前へ付け替えられる。
  飛ばして続ければ、欠けたことが誰にも見えないまま残りが並ぶ
- **置き場の現在地が手元のカーソルより手前なら、手元を捨てて最初から取る。** 並び順は巻き戻らないので、
  手前に居る置き場はこのカーソルを数えた置き場ではない。置き場が `409` で同じことを言うこともあり、
  **やり直しは1周に1回だけ**（無限に取りに行かない）
- 契約の版が違う置き場は読まない。**アプリを更新してもらう話**であって、再試行する話ではない

**最初の1周だけは、待たせ方が他と違う**（`lib/first_sync.dart`）。以後の1周は中身の在る画面の裏で
数行が届くだけだが、初回は空の端末へバックログ丸ごとが来る。

- **数で出す。** 取り込んだ件数が増えるのを見せる。棒だけだと、遅いのか壊れたのかが読めない
- **件数は「残り」を言わない。** 置き場に何行在るかは `GET /meta` の答えに無く、`seq` は
  書き込みの回数なので、一度直された行は2つ数えている。棒の側だけが並び順の終わりを知っている
- **離れても続きから。** カーソルはページごとに進むので、中断の代償はそのページだけ。そう書いておく
- **終わりに触覚を1つ、祝いの画面は出さない。** 見たいのは中身であって、成功の報告ではない
- **止まった理由ごとに次の手が違う。** 届かない・切られた・版が新しい・置き場が建て直された——
  「うまくいきませんでした」1本にすると、全員が同じ間違った次の手へ行く

## 単独で完成していること

ストアの承認スケジュールは制御できない。このビルドが、まだ対応していない amenbo 本体や
プラグインと同居する状況は普通に起こる。だから検証に本体もプラグインも要らない形にしておく。
CI（[`.github/workflows/app.yml`](../.github/workflows/app.yml)）が `app/` だけで回るのは、
その要件をそのまま置いたもの。

ペアリング前は正常系。エラーにも空白にもせず、何をすればよいかの案内を出す。

## 署名

署名の情報はリポジトリに入れない。実機ビルドのときは Xcode で Team を選ぶ。
CI は `--no-codesign`。

## 動かす

```
make build   # pub get と analyze
make test    # flutter test
make apk     # Android。Android SDK が要る
make ipa     # iOS。Mac と Xcode が要る。署名はしない
```

## 実機の画面を、誰も端末を持たずに読む

```
make screen-android   # ピクセル（PNG）とビュー階層
make screen-ios       # セマンティクスツリー（テキスト）
```

どちらも `lib/probe_screen.dart` を焼く。**本物のアプリに、セマンティクスを点けただけのもの**である。
Flutter は自前で描くので、読み上げる者が居ないアプリは OS から見ると**中身の無い1枚の面**でしかない——
点けることが、どちらの OS にも読むものを与える唯一の手段になる。

取れるものは OS で違う。Android は外から丸ごと見えるのでピクセルも階層も取れるが、
**iOS は外から中が見えない**ので、アプリが書き出したファイルを引く（撮影の道は無い）。
結果は `build/device-screen/` に出る。

**終わったら本来のエントリポイントを焼いて入れ直す。** バンドル ID は同じなので、
放置すると端末に残るのはプローブになる。

見た目の崩れに実機は要らない——**ゴールデンテスト**の領分。実機で見るのは OS が絡む挙動だけ。
