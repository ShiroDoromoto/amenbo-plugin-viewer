# app — Amenbo Viewer（Flutter）

iOS と Android を1本で作る。`ios/` と `android/` は Flutter がこの下に生成する。

**Flutter を選んだのは、プロジェクトを跨いで技術構成を揃えるため**で、ここ単体の最適解を採ったのではない。
構成がばらつくと保守の作法がプロジェクトごとに変わり、その負担は実装量の差より長く効く。

| | 値 |
|---|---|
| ストア表示名 | Amenbo Viewer |
| バンドル ID / パッケージ名 | `work.amenbo.viewer` |
| Dart のパッケージ名 | `amenbo_viewer` |
| iOS の最低対応 | 15.0 |

表示名は日英どちらでも通るので、言語ごとに変えず揃える。

**iOS の下限を下げても、対応機種は1台も増えない。** iOS 15 は iOS 13 と同じ端末まで上がる
（下限は iPhone 6s と第1世代 SE）。13 まで戻して届くのは5年以上 OS を更新していない利用者だけで、
代わりに手元に実機の無い OS が2つ増える。

iOS は2経路を持つ。アプリ専用の iCloud コンテナ（`iCloud.work.amenbo.viewer`）を読む経路と、
Cloudflare へ HTTPS で取りに行く経路。Android は Cloudflare 経路だけ。
復号した後の扱いはどちらも同じで、書き戻さない。

**iCloud 経路に、この端末の操作は無い。** 利用者はフォルダを選ばない——置き場はエンタイトルメントで
与えられ、コンテナの `Documents/` を直に読む（`ios/Runner/ICloudContainerBridge.swift`）。
そのディレクトリを作れるのはアプリだけなので、**mac 側の書き先はアプリを一度起動して初めて生える**。
iCloud にサインインしていない状態は失敗ではなく、`available: false` として扱う。

## 根と、行き先

どの画面を出すかを決めるのは `lib/home.dart` の1か所だけ。

- **経路が無いあいだは案内**（ペアリングも、届いた行も無い状態）。空の一覧は「何をすればよいか」を言えない
- **読めたら最初の同期へ入り、終わったら一覧へ抜ける**。祝いの画面は挟まない
- **消したら案内へ戻る。** 設定は積まれた画面なので、`true` を返して閉じ、骨組みが根に伝える
- 届いた行が在れば、ペアリングが無くても案内は出さない。**iCloud 経路にこの端末の操作は無い**ので、
  設定を促す画面は「もう動いているもの」を指して出ることになる

下端のタブは3つ（タスク／決定記録／さがす）。**タブは行き先で、絞りは画面の中身**——だから
分類チップを押しても、**1本のリストの面を積むだけでタブは移らない**。

**タスクの面は、状態四つの切り替え**（未着手／進行中／ブロック／完了）。分ける単位は Amenbo の状態
そのままで、前提が足りているかどうかでは分けない——それは導いた値で、日をまたげば同じタスクでも答えが
変わる。導いた値で分けると、PC で見た並びとここの並びが食い違う。**待っているものは未着手に残し、
その行に砂時計の印と待っている相手を出す**。**相手を名乗れないなら印は出さない**——Amenbo の `blocked` は
前提ではなく状態そのもので、状態は切り替えと行の印と読み上げがすでに言っている。
切り替えの見出しには件数が付き、**0 件の状態も出す**
（「ブロックは0件」は読みに来た人が知りたい答えで、印が消えることではない）。

**一つの状態は、そのまま端まで辿れる**。50件ずつ読み、下端に着いたら次を読み込む。**二十行で切って
別の面へ送るのはやめた**——次に取るものを探しに来た人に、面をまたがせない。

**完了は期間で切らない**。新しい順に全部並べ、**日付が変わるところに見出しを入れる**。端末は全件の
写しを持っているので、切っても取りに行くものは無い——手元にある行を隠すだけになる。

**決定記録は、さがすを通らずに開く**。日頃そのまま読むもので、探しに行くものではない。中身は新しい順の
一覧1本きりで、答えが出ていないものも却下されたものも落とさない——まだ答えていない1本が、いちばん読む
値打ちがある。

**さがすと決定記録は、訪れるたびに作り直す**。さがすは常に全体から始まり、決定記録はその時点のストアを
読み直す。前の画面から持ち越した絞りも、骨組みを組んだ時の古い一覧も、利用者が頼んだものではない。
タスクの画面だけは作り直さない——自分から取ったぶんをピルの裏で待たせているので、作り直すと
頼まれていない行が入る。

**設定は下端に置かない。** 親指が届く一等地は毎日読むものに使う。設定にあるのは2つの選択と2つの
出口だけで、開くのは月に数えるほど——**タスクの画面の右上**から積む。

**幅があれば、開いたものは一覧の隣**（`TwoPane`）。**狭いときは積む**——2面のまま横で入れ替えると、
端からのスワイプで戻る道が無くなる。**決定記録だけは幅があっても積む**。開く元が一覧とはかぎらず
詳細からのことも多いので、隣を入れ替えると戻り先が読めなくなる。

**同じ幅で、下のタブは横のレールになる**（`home.dart`）。下端が親指の一等地なのは片手で持ったスマートフォンの話で、
タブレットや横向きではいちばん遠い場所になる。**レールでも語は消さない**——絵だけの行き先は押すまで分からない。

## 見た目の作法

画面ごとに決めるとばらつくものを、テーマと共通ウィジェットに落としてある（`lib/ui/`）。

**数字は1枚に集めてある**（`lib/ui/tokens.dart`）。色・余白・角丸・文字の大きさは、**Amenbo 本体が
持っている一組をそのまま写した**もので、こちらで決め直していない。同じバックログを読む道具が2つあって
色も言葉づかいも違えば、利用者には別の製品に見える。写しなので、本体が動いてもこちらは追いかけない——
そのときは手で揃え直す。

写すのは4つ（色・余白・角丸・文字の大きさ）だけで、**画面の組み方は写さない**。本体は机の上の広い画面で
見るもの、こちらは片手で数十秒読むもので、置き方の理屈が違う。

- **画面は数字を書かない。** 余白は目盛り（`Space`）、角丸は `Corner`、線幅は `Stroke`、
  文字の大きさは `Lettering`。1か所に集まっていないと、あとから全体を動かせない
- **余白の目盛りは本体のまま**（4・6・8・12・16・24・32）。写すときに外れた値は近い段へ寄せた。
  一覧の左右は16、散文の画面は24（`Space.gutter` / `Space.pageGutter`）
- **Material にある色は `ColorScheme` から、無い色は `palette(context)` から。**
  状態・優先度・期限の色は Material に役が無いので後者で持つ。明るい側と暗い側の両方が揃っている
- **Material 3 を1セットで両 OS に出す。** プラットフォームで見た目を変えない
- **フォントは同梱しない。** どの言語も端末の書体で描く（`pubspec.yaml` の `fonts:` は空のまま）。
  19言語ぶんの字形は数十メガバイトになり、数十秒開く道具が払う値段ではない
- **大きさを自分で書かない。** 文字は OS の設定に従う。表題は2行で止める（`RowTitle`）
- **押し場所は指の大きさ**（`TapTarget`——`Layout.touch` を読むのはここだけ）。描く文字は読む大きさのまま、
  押しに答える面だけを広げる。文の中に置いた数字も、上のバーの番号も、押されるものは同じ寸法にする
- **状態を色だけで表さない。** 優先度・期限切れ・状態は、かたちと語を併せる（`marks.dart`）
- **行は1つの塊で読み上げる。** `rowLabel` が文を作り、`SpokenAsOne` が中の記号を黙らせる
- **時刻は相対。** 絶対時刻は長押しで出す（`TimeOnHold`）。日付と時計の書き方は言語と端末に従う
  （`TimeFace`——→「言葉も1枚に集めてある」）
- **触覚は2回だけ**——引き下げた更新の反映と、初回同期の完了。**音は鳴らさない**（`touch.dart`）
- **幅があれば2面**（`TwoPane`）。判定は幅で、端末の種類では決めない。**一覧側は幅に応じて伸びる**
  （画面の3分の1・上下限つき）。固定にすると、広い画面で増えた分がすべて右側に乗る
- **どの面も読める幅で止めて、中央に置く**（`Measured`）。1行が長すぎると、次の行の先頭がどこか分からなくなる。
  2面を通らない面——押して開く画面と、隣に何も開かない決定記録の一覧——も同じ規則で止める
- **止める幅は2つ**。散文は行に沿って読むので `Layout.readable`、行の並びは左端を縦になぞって読むので
  それより狭い `Layout.listPaneMax`。**一覧を散文の幅で止めると、伸びるのは誰も端まで読まない表題だけ**。
  どの面がどちらで止まるかは、タブレットの幅で描いて測る（`test/wide_screen_test.dart`）
- **番号は押せばコピー**（`RefChip`）、詳細から**共有**は3行だけ（`handoffText`——番号・表題・状態）。
  書き戻せないので、PC へ渡す橋はこの2つきり。**本文は載せない**——読み返す先は PC にあり、
  貼り付けた notes の壁は誰も読まない
- **行の骨格は1つ**（`RowSurface`）。**先頭は幅の決まった一列**（`RowLead`——優先度のかたち）で、
  何を着ている行でも**表題の左端が動かない**。優先度はここでは語を持たず**かたちだけ**（読み上げは行の1文が持つ）
- **行と行のあいだには線を引く**。行の高さが揃わないので、線が無いと長い表題と上の行の添えが1つの塊に見える
- **表題の下は、点で並べず段を付ける**（`task_row.dart`）。先頭に来るのは**開くかどうかを決める1つ**——
  止まっている理由か期限——で、そのあとの添え（プロジェクト・AI・コメント数・動いた時刻）は
  **一段小さく薄い**。入りきらなければ折り返す。**本文の抜粋は出さない**
- **一覧の中の見出しは、行の表題より太い**（`ListHeading`）。見出しが行より弱いと、区切りが1本の長い列に見える。
  **見出しは件数を持たない**——数を出す場所は、状態を選ぶ切り替えの側
- **抜粋が出るのは、さがすで表題以外に当たったときだけ**（3行目）。なぜその行が結果に居るのかは
  他のどこにも書けない。表題に当たったぶんは出さない——行がその1行だからで、繰り返せば
  「検索が動いた」以上のことを言わない
- **決定記録の行も同じ骨格**（`decision_row.dart`）。優先度も期限も無く、代わりに**誰かが答えたかどうか**を出す
- **詳細の骨格も1つ**（`detail.dart` を `task_detail.dart` / `decision_detail.dart` が着る）——
  番号・プロジェクト・表題・状態・本文・つながり・コメントの順。タスクが「止まっている理由」を本文の上に
  置く場所に、決定記録は**「あなたの答えを待っている」**を置く（何件のタスクが止まっているかも添える）
- **頭は4つを同じ強さで並べない**（`DetailHead`）。**表題がいちばん強く**、プロジェクトと状態はその上下に
  一段小さく置く。**番号は上のバーへ**——押せばコピーできる場所は変わらない
- **バーは、いま読んでいるものの名前を言い続ける**（`DetailFrame`）。頭が上へ流れたら、番号の隣に表題が出る。
  詳細はスクロールされるもので、頭が消えたあと画面には何を読んでいるかが残らない
- **節の見出しは、上に広く下に狭く**（`SectionHeading`）——上の空きが画面を節に割り、下の空きが見出しを
  下の行に結ぶ。同じ空きで挟むと、見出しはどちらの節のものか分からなくなる
- **アプリの断りは枠線、本文の引用とコードは塗り**（`NoticePanel`）。同じ面で描くと、アプリの言葉が
  誰かの書いた1行に見える
- **本文の Markdown は自前**（`markdown.dart`）。描くのはバックログが実際に使う範囲だけで、
  **mermaid はソースのまま**・**画像は取りに行かず枠と URL**・**`##` の節は畳める**（最初の1つだけ開く）。
  範囲外の記法は書かれた文字のまま出す

**文言は画面に書かない。** どの語も `lib/l10n/` の1枚から引く（→「言葉も1枚に集めてある」）。

**どう立っているかは上端の帯1本**（`state_band.dart`）。7つの状況を1本に集約し、**画面を覆わない**——
帯の下の像はいつでも読める。**どれもエラー色で描かない**（オフラインは故障ではない）。

**持ち上げるのは、利用者に打つ手がある3つだけ**——鍵が合わない・締め出された・iCloud に入っていない。
アクセントの面に印を付けて、出口を釦の顔で出す。**3つが上限**で、増やすほど持ち上げた意味が減る。
残りは静かな帯のまま——**静けさは無言ではない**ので、起きていること自体は言葉で言う。
圏外も「まだ届いていない」も利用者の落ち度ではなく、驚かせる意味がない。
複数当てはまるときは**原因が不在に勝つ**——「まだ届いていません」は不在を言うだけの唯一の行で、
原因が分かっているのにそれを出すのはアプリの唯一の嘘になる。

**上端は1行きり——いつ取れた像かと「取りに行く」だけ**（`now_screen.dart`）。同じことを聞かれたときの
答えの前半と後半なので、離さない。開いて最初に目が行く場所なので、**読みに来たものはその下から始める**。
**取りに行く手は循環矢印の絵で置き、語は読み上げに渡す**——意味の固まった数少ない絵のひとつで、
取った時刻の隣に在れば他の意味には読まれない。1行のなかで2つの文字列が場所を取り合うのを避ける。
引き下げは同じ取得への近道として残すが、**目に見えない操作を唯一の道にはしない**。
経路を持たない端末には釦を出さない（押しても何も起きない釦を置かない）。

いつ取れた像かは**相対時刻を使わない**——時計の狂った端末でも、取った時刻の「時」は正しく言えるから。
ただし**今日でなくなったら日を添える**（英語なら `yesterday 09:14` / `Aug 2 09:14`——
日の書き方はその言語のもの）。
電波の無いまま夜を越えると、時刻だけの行は今朝のものに読める。

**何も無い画面は、起きたことと次の一手を出す**（`EmptyFace`）。中央に1行だけ置くと、一覧が空だとは
分かっても、そこから先へ進む手がかりが無い。印・起きたこと・次にどうするかの3つを置き、この画面から
踏める道があれば釦で出す（結果が空なら「全部を出す」——語も絞りもまとめて外す）。次の一手が別の画面に
あるときは、その場所を言うだけにする——**ここに無い操作を釦の顔で出さない**。
まだ何も届いていない端末の帯（`state_band.dart` の `whole`）も同じ並びで、読む側から見れば同じ場面になる。

**リストの並べ替えをアニメーションで見せない。** 読んでいる場所が飛ぶ。並びが変わる面では
`AnimatedList` を使わない。

**動くのは2か所だけ**（`Motion`）——本文の節の開け閉めと、新しく届いた知らせの出入り。
どちらも押していないのに中身が入れ替わる場所で、動きが無いと何が起きたのか読み取れない。
**画面から画面への移り変わりは端末の既定のまま**にする。この道具は数十秒しか開かれないので、
凝った動きはその数十秒を削るだけになる。
**動きを減らす設定の端末では動かさない**（`Motion.asked`）——好みの問題ではなく、動きで気分が悪くなる人が居る。
一覧は動かないままなので、**知らせが去る動きが、溜まっていた行が入ったことを言う唯一の合図**になる。

## 言葉も1枚に集めてある

数字と同じ扱いで、**画面に出る言葉は1枚に集めてある**（`lib/l10n/`）。画面は文字列を書かない——
`Words.of(context)` から引く。19の言語へ広げる先があるからで、散らばったままでは
「どこが訳されていないか」を数える手がない。

- **言語ごとに1枚**（`app_<言語>.arb`）。**`app_en.arb` が原本**で、他はそれの語を差し替えた写し。
  19枚とも埋まっている。**空でも置く**——枚数がアプリの名乗る言語そのものなので、
  枚が無ければその言語は存在しないことになる
- **写しは訳文ではなく、その言語の言葉として書く。** 本体に同じ意味の語があればそこから引き、
  無いものはこの製品の言葉として選ぶ。書き終えた後の保守はこのアプリの持ち物で、本体の変更は追いかけない
- **写しに説明（`@鍵`）は書かない。** 説明は原本のもので、写しに重ねると同じ文が19か所に散る
- **`Words` は生成物**（`flutter gen-l10n`）。**リポジトリに入れない**——原本から導けるので、
  `make build` / `make test` が読む前に書き出す
- **端末の部品も同じ言語で出る。** ライセンス画面・文字欄のメニュー・スクロールバーの読み上げは
  Flutter が持っている語で、`Words.localizationsDelegates` がそれごと渡す。こちらで書く語ではない
- **どの鍵がどの言語で埋まっていないかは、ゲートが数える**（`test/l10n_test.dart`）。
  **足りないのは赤にしない**——辞書は鍵の後から書くもので、書き始めた瞬間に赤くなるゲートでは
  誰も書き始められない。**赤にするのは3つ**——原本に無い鍵が写しに在る（打ち間違いか、
  使われなくなった鍵）／原本の語に説明が付いていない（訳す人は画面を見ていない）／
  枚数とアプリが名乗る言語が食い違う
- **数と語尾は鍵の側で分ける**（`{count, plural, ...}`）。1件と2件で語尾が変わる言語は2つでは足りず、
  呼ぶ側で `count == 1` を書くと、その分岐は英語の形のまま固まる。**原本の腕は `one` と `other` の2本**——
  英語に要るのがその2つというだけで、ロシア語やポーランド語の写しは `few` / `many` を足してよい。
  **数を語に混ぜる鍵が複数形になっているかは、ゲートが見る**（`test/l10n_test.dart`）
- **語の長い言語で幅が保つかも、ゲートが見る**（`test/long_words_test.dart`）。ドイツ語・ロシア語・
  ポーランド語で全画面を、いちばん狭い端末（320）と文字を2倍にした端末で描く。**はみ出したら赤**——
  版組は英語で組んでいるので、英語で収まった幅は他の言語では収まらない。折り返して背が伸びるぶんと、
  末尾が…になるぶんは通る。ここが見るのは画面の外へ出た字だけ
- **数え終えていない数は、別の鍵にする**（`more` と `moreCapped`）。`999+` は数ではないので、
  どの言語もそれには合わせられない。同じ鍵に流すと、片方の形しか書けない鍵になる

**表示する言語はアプリでは選ばせない。** 端末の設定に従う——同じことを選ぶ場所を2つ作ると、
どちらが効いているのか分からない瞬間が生まれる。

**どの1枚を引くかは自分で決める**（`lib/l10n/language.dart`）。Flutter の既定の照合に任せないのは、
**書き方が2つある言語で、端末の申告だけでは決まらない**から。

- **中国語は2枚。** 字体を名乗った端末はそれに従う。**場所しか名乗らない端末も実は名乗っている**——
  台湾・香港・マカオは繁体、それ以外は簡体。どちらも名乗らなければ簡体（`app_zh.arb` が簡体、
  `app_zh_Hant.arb` が繁体）
- **ポルトガル語は1枚**（`app_pt.arb`・ブラジルの語彙）。ポルトガルの端末もこれを読む。
  選ばない語は混じるが、**英語よりは全部近い**
- **どれにも当たらなければ英語。** 並び順で先頭に来た枚ではない——並びは言語を足すたびに動く

**言い回しは鍵から、書き方は言語から**（`lib/ui/time.dart`）。「たった今」「◯分前」「昨日」は
その言語の言い回しなので鍵に在る。月の名前・日と月のどちらが先か・時計が12時間か24時間かは、
その言語でものを書くときの決まりなので `intl` から引く。19人の訳者に日付の並べ方を考えさせない。

**時計だけは端末の設定が勝つ**（`TimeFace`）。24時間表示に切り替えた人は、どの言語のアプリでも
14:02 で読みたい。切り替えていなければ、その言語の習慣に従う。

**例外は「どの断りか」を運び、文は画面が選ぶ。** 取り込みと封と QR の読み手
（`cloudflare_intake.dart` / `icloud_intake.dart` / `record_envelope.dart` / `pairing_code.dart`）は
文を組み立てない。運ぶのは種別（`IntakeFailure` / `SealProblem` / `CodeProblem`）と、
**訳さない値**——版の番号、状態コード、止まった場所、宛先——だけで、文にするのは出す側の
2画面（`whatStopped` が初回同期、`troubleWith` がペアリング）。

- **止まった場所や状態コードは持つが、出さない**。読むのはスタックトレースを見る人で、
  利用者に「`task/2833` で止まった」と言っても打つ手は変わらない
- **初回同期では版の番号を出さない**。合わないと分かれば出口は同じで、このアプリが読む版は
  「これは何か」の画面に在る
- **ペアリングでは版の番号を出す**。カメラの前に居る人は2台の間に立っていて、答えは
  「どちらを更新するか」になる

## 顔——アイコンと起動画面

どちらも **Amenbo 本体のアメンボのマーク**で、スマートフォン向けに別の絵は描かない。同じ製品として並ぶものに
別の絵を当てれば、利用者には別の製品に見える。

マークは**座標として写してある**（`tool/brand_mark.dart`）。色や余白の数字を写したのと同じ理由で、
本体のリポジトリが隣に無くても焼ける。ストアの横長の画（下記）も同じ数字を読む。焼き直すのは1行:

```
dart run tool/gen_brand_assets.dart
```

iOS のアイコン一式と起動画像、Android のランチャーアイコンと adaptive の前景が出る。
**ピクセルを手で触らない**——本体のマークが動いたときに動かすのは、座標の側。

- **アイコンの下地はマーク自身の生成り色**。アプリの下地ではない——アイコンが載るのは壁紙の上で、
  アプリの上ではない
- **起動画面は下地色とマークだけ**。明るい側と暗い側で下地が変わり、マークは変わらない
  （あの青と珊瑚色は、どちらの下地にも載る）
- **その下地色は `lib/ui/tokens.dart` の `bg` と同じ値**（Android は `colors.xml`、iOS は `LaunchBackground`）。
  ずれると、起動の瞬間に一度光る

## 手元の持ち方

復号した像は **SQLite に行のまま置き、画面はそこへ問い合わせた結果だけを持つ**（`lib/store/`）。
全件を配列に読んでから絞る形にしない——バックログは消さずに積むもので上限が無く、iOS は
メモリ圧で背面のアプリを落とすので、抱えるほど前面復帰のたびに作り直すことになる。

| 面 | 一度に持つ量 |
|---|---|
| タスクの面の各状態 | 50件ずつ |
| リストの面（さがす・分類の値）と決定記録の面 | 50件ずつ |
| タスク詳細のコメント | 最新3件から20件ずつ遡る |
| 総数 | 999 で数えるのをやめる |

置き方は2段になっている。**届いた行はそのまま `record` に置き**（契約の `テーブル名/行 id` がそのまま鍵）、
並べ替えと絞り込みに要る短い列だけを別の表へ写す。長い本文が1か所にしか無いので写しは安く、
表の形を変えても**手元の行から作り直せる**——アプリの更新のたびに再ダウンロードさせない。

**この端末が自分で書く覚えは、置き場の入れ替えでも残す**（`MetaKey.deviceOwn`）——設定と、
直前に打った語・直前に開いた行。**どの行を読んだかは覚えない**——ここに来て見ているのは PC で
見ているのと同じ姿で、受信箱ではない。だから未読の印も、前に開いた時刻からの数え上げも持たない。
置き場が建て直されて手元を捨てるときも**ここだけは残す**——PC が全部送り直したからといって、
利用者の好みが変わったわけではない。

検索は FTS5 の索引に任せる。トークナイザは **trigram**——日本語には語を切る空白が無い。
3文字に満たない語だけは索引が答えられないので `LIKE` に落ちる（`QR` のような語が実際に打たれる）。

SQLite は **`sqlite3` パッケージが同梱するものを使う**（OS のものを呼ばない）。端末・手元・CI で
同じ版が動き、FTS5 と trigram が在ることを版の当たり外れに任せずに済む。

iOS では DB に `NSFileProtectionComplete` を付け、**ロック中は読めなくする**（`ios/Runner/FileProtectionBridge.swift`）。
読むのは起動時と前面復帰時だけなので、ロック中に読めなくても困らない。Android に相当するものは無い——
アプリ専用の領域に置き、端末の暗号化に委ねる。**守る対象は鍵1つに絞る**（本文は平文で置く）。

## 設定と接続

引き下ろせるのは2つだけ——**いつ取りに行くか**と**明るさ**（`lib/settings.dart`）。読む道具なので、
触れるところが増えるほど迷う場所が増える。**画面の作りは選ばせない**——並びも見せ方も、場面から
一度決めるもので、渡せば利用者がリーダーを調整することになる。

- **絞りはここに置かない。** 何を見せるかは見ている画面で変えるもので、設定の奥に置くと、
  一覧を見ている人からは手が届かない。ここにあった「終わったものを見せる期間」は、
  端末が持っている行を隠していただけだった

- **更新に間隔を持たない。** 常駐せず自分で起きないので、分を選ばせても何も起きない。
  「自動」は起動時と前面復帰時の2回きりで、この設定が決めるのは**アプリが自分から動くかどうかだけ**。
  利用者から頼む道（前の画面の「取りに行く」と引き下げ）は、どちらを選んでも残る。
  打つのは根（`lib/home.dart`）で、**自分から取ったぶんは黙って混ぜない**——上端のピルに数えて待つ
- 選んだ値は DB の `meta` に置き、**置き場を取り直しても消さない**（`MetaKey.deviceOwn`）。
  あれは端末の持ち物で、PC が全部上げ直したからといって利用者の好みは変わらない
- 明るさだけは根が読む。**起動で待つのはこのローカルの DB だけ**で、通信は待たない——
  先に描いてから直すと、頼んでいない明滅を見せることになる

接続の画面（`lib/connection_screen.dart`）は**この端末1台の話しかしない**。
この端末の名前・経路・最後に取れたもの・ペアリングし直す・この端末のデータを消す、で終わる。

- **他の端末を並べない。** 読み取りトークンを足すのも切るのも書き込み側の口で、
  アプリが持っているのは自分の1つきり。並べれば、押せない操作を並べることになる
- **自分の名前だけは出す。** 切るのは名前でやるので、名前が出ていないと PC の行のどれが
  手元の端末なのか照合できない。名前を載せていない古い QR で組んだペアリングでは、この行ごと出さない
- **URL はホストだけ出す。** 画面は人が写真に撮って見せるもので、トークンと鍵はそこに写る
- 消すのは**復号した像と鍵**の2つで、置き場へは何も言わない。置き場は利用者のものなので、
  PC はそのまま書き続ける

「これは何か」の画面（`lib/about_screen.dart`）は、**版・どこから入ったか・読む契約の版・
プライバシーポリシー・ライセンス**の5つ。**外へ出るのはポリシーだけ**で、それも端末のブラウザに渡すだけ。
残りは取りに行かないので、通信の無い場所でも読める。

- **ポリシーはアプリの中から辿れないといけない。** 両ストアの審査がそこを見ていて、
  申告の欄に URL を書いてあるだけでは足りない
- **URL は1か所に置く**（`privacyPolicyUrl`）。19言語とも同じ1本で、言語の出し分けはサイト側がやる。
  2か所に書くと、古いほうが残る
- **開かなかったら黙らない。** ブラウザを持たない端末はありうるので、渡せなければ URL そのものを画面に出す
  （渡す相手が見えるように、Android のマニフェストの `queries` にブラウザを書いてある——
  書かないと押しても何も起きない）

**どこから入ったかは、端末に訊く**（`lib/build_origin.dart`）。配って試す版とストアの版は識別子も版も同じなので、
画面の他のどこを見ても見分けられない。**アプリが名乗るしかない。**

- **iOS はレシートの名前で決まる。** `sandboxReceipt` なら TestFlight、`receipt` ならストア。
  Xcode から入れたものはレシートを持たない（URL は返るが、ファイルが無い）。中身は検めない——
  署名を検めるのは購入を開けるときの作法で、ここが要るのは外側に書いてある名前だけ
- **Android は入れた側のパッケージで決まる。** Play なら Play——**それ以上は言えない**。
  掲載のものもテスト用トラックのものも、記録には同じ Play しか残らない。**そこは正直に出す**
- **分からないときに嘘をつかない。** 知らない語・失敗した呼び出し・向こう側が無い（テストや Mac）は
  すべて「分からない」に落ちる。いちばんありそうな方へ寄せない
- **答えが来るまで、その行を出さない。** 先に「分からない」と出して直すと、待ち時間を報告することになる

## ペアリング

Cloudflare 経路の設定はこれ1つきりで、**PC の画面に出た QR をカメラで読む**だけ（`lib/pairing_scan.dart`）。
載っているのは版・URL・この端末の読み取りトークン・暗号鍵・この端末の名前で、
読み替えは `lib/pairing_code.dart` が持つ。

入口は案内の画面（`lib/pairing_guide.dart`）の**ボタン1つだけ**。iCloud 経路のカードにボタンは無い——
あちらの支度は全部 mac の側で、押して何も起きないボタンは「壊れている」と読まれる。
読めた後に**どの画面へ抜けるかは案内が決めない**。ペアリングを上へ渡すところで役目が終わる。

- **カメラを求める前に理由を1行出す。** 断りなく出た OS の確認は反射で答えられ、「いいえ」は
  この端末で唯一の設定作業を1タップで塞ぐ
- **読めた瞬間に保存して閉じる。** 確認のボタンは挟まない——読み直しはいつでも効くので、
  挟んだところで利用者に base64 を検分させるだけになる
- **断られても終わりにしない。** 設定アプリへの導線を出す。**戻り道はこれ1本きり**——
  写真から読む道は、トークンと鍵を写真ライブラリと iCloud へ出すことになるので持たない
- **版は他の3つより先に確かめる。** 先の契約はフィールドを動かしているかもしれないので、
  「URL が無い」は正しい問いへの誤った答えになる
- **合う合わないだけを言わない。** 別のアプリの QR・新しい版・長さの違う鍵は、それぞれ次の手が違う
- **http の置き場は受けない。** 載っているトークンはこの端末の入場券で、平文で送れば端末のものでなくなる
- **鍵はここで一度開いてみる。** 長さの違う鍵は最初の同期でも同じように失敗するが、
  画面に向けている今なら利用者に打つ手がある
- **名前が無い QR も通す。** 名前は3つの秘密より後から載せたもので、断れば通るはずの
  ペアリングを、画面に出す1行のために断ることになる

カメラと権限の2つのパッケージは**この画面だけのもの**で、以後どこからも呼ばれない。

## 取り込み

**取りに行く口は1つ**（`lib/home.dart`）。どちらの経路を回すかは端末が持っているもので決まる——
ペアリングが在れば Cloudflare、無ければコンテナ。叩くのは**起動・前面復帰**と、利用者が頼む
**上端の取りに行く・引き下げ**。前の2つは設定で止められ、あとの2つはどちらを選んでも残る。
1周の報告はどちらの経路も同じ形なので、上端の帯はそのまま両方の結果を読む。

- **初回同期の画面が出るのは Cloudflare 経路だけ**。あれは QR を読んだ直後の待ち時間に出すもので、
  iCloud 経路にこの端末の操作は無く、待っている人が居ない
- **サインアウトは、届かないのとは別の行**。1周が届かずに終わったら、コンテナへもう一度訊いてから
  帯の行を決める。起動時の答えを信じ続けると、途中でサインアウトした端末に「オフライン」と出て、
  **iPhone の設定を開けば直るという話が消える**

**通信するのは Cloudflare 経路だけ**（`lib/cloudflare_intake.dart`）。画面はローカルの DB しか読まない。
置き場の並び順は増える一方で、端末は自分が読んだ点を覚えている——だから1周は
「`GET /meta` でどこまで来ているかを訊く」「先に居るなら、その先をページごとに取る」の2つで終わる。

- **1ページ開いたらその場で書く。** 全量を組み立ててから保存すると、初回同期という
  いちばん落とされやすい瞬間に、開いたぶんを丸ごと捨てることになる。ページ単位なら
  中断の代償はそのページだけで、カーソルは入ったぶんまで進んでいる
- **版はページが尽きてから採る。** `more` が続くあいだは半周ぶんしか持っていないので、
  そこで版を書くと「最新に追いついた」と嘘をつく
- **開かないレコードは飛ばさない。** 置き場へ書ける相手はレコードを別の名前へ付け替えられる。
  飛ばして続ければ、欠けたことが誰にも見えないまま残りが並ぶ
- **置き場の現在地が手元のカーソルより手前なら、手元を捨てて最初から取る。** 並び順は巻き戻らないので、
  手前に居る置き場はこのカーソルを数えた置き場ではない。置き場が `409` で同じことを言うこともあり、
  **やり直しは1周に1回だけ**（無限に取りに行かない）
- 契約の版が違う置き場は読まない。**アプリを更新してもらう話**であって、再試行する話ではない

**iCloud 経路は、置き場が台帳ではなくフォルダ**（`lib/icloud_intake.dart`）。訊く相手が居らず、
カーソルも無いので、1周は在るものを1回なめる——`meta.json` が契約の版と像の版を名乗り、
`records/<テーブル名>/<行 id>.json` が1レコードずつ持つ。

- **封がされていない。** ここは端末自身の iCloud コンテナで、利用者自身のアカウントの中——
  手元の DB と同じ守り方なので、行はそのまま置かれる。**鍵を要求しない**のは、鍵が生まれるのは
  Worker を立てる工程で、mac だけの人はそこを通らないから
- **消えたことは、ファイルが無いことでしか伝わらない。** 墓標を置いても誰も片付けられないので、
  **手元に在って置き場に無い鍵は、その1周で消す**
- **版は最後に置く。** PC がレコードを置いてから版を書くのと同じ順で、こちらもレコードを書いてから版を採る。
  途中で切れた1周は版を持たないので、次の1周がもう一度なめ直す（半周を「追いついた」と読まない）
- **鍵は2度書かれている**——ファイルの置き場所と、レコードの中。**食い違えばそこで止める**。
  封が無い経路なので、行が名乗りどおりの場所に在ると言えるのはこの照合だけ
- **iCloud が使えない状態は、待ちとして出す。** サインアウトも iCloud Drive オフも利用者の落ち度ではない
- **待つのに上限を置く**（Cloudflare 経路と同じ30秒）。実体が端末に無いファイルは渡してくる相手が要るので、
  圏外だと読みが返ってこない。**上限は iOS 側にも渡して協調読み取りごと打ち切る**——
  こちらが待つのをやめるだけでは、返らない読みがブリッジに積み残る

**最初の1周だけは、待たせ方が他と違う**（`lib/first_sync.dart`）。以後の1周は中身の在る画面の裏で
数行が届くだけだが、初回は空の端末へバックログ丸ごとが来る。

- **数で出す。** 取り込んだ件数が増えるのを見せる。棒だけだと、遅いのか壊れたのかが読めない
- **件数は「残り」を言わない。** 置き場に何行在るかは `GET /meta` の答えに無く、`seq` は
  書き込みの回数なので、一度直された行は2つ数えている。棒の側だけが並び順の終わりを知っている
- **離れても続きから。** カーソルはページごとに進むので、中断の代償はそのページだけ。そう書いておく
- **終わりに触覚を1つ、祝いの画面は出さない。** 見たいのは中身であって、成功の報告ではない
- **止まった理由ごとに次の手が違う。** 届かない・切られた・版が新しい・置き場が建て直された——
  「うまくいきませんでした」1本にすると、全員が同じ間違った次の手へ行く
- **押しても同じになる理由には、押すものを出さない。** 切られた端末と、契約が新しすぎる置き場は、
  次の手が PC とストアの側にある。もう一度の釦を並べれば、行き先を書いた文の隣で足踏みさせることになる

## 実機の画面を、誰も端末を持たずに読む

```
make screen-android   # ピクセル（PNG）とビュー階層
make screen-ios       # セマンティクスツリー（テキスト）
```

どちらも `lib/probe_screen.dart` を焼く。**本物のアプリに、セマンティクスを点けただけのもの**である。
Flutter は自前で描くので、読み上げる者が居ないアプリは OS から見ると**中身の無い1枚の面**でしかない——
点けることが、どちらの OS にも読むものを与える唯一の手段になる。

取れるものは OS で違う。Android は外から丸ごと見えるのでピクセルも階層も取れるが、
**iOS は外から中が見えない**ので、アプリが書き出したファイルを引く（撮影の道は無い）。
結果は `build/device-screen/` に出る。

**そのままでは、開いた画面しか読めない。** アプリは毎回同じ画面で開き、この道具は何も押さないから。
押した先を読むなら**待ち時間を延ばして、その間に人に歩いてもらう**——プローブは3秒ごとに2分間
書き続けるので、止まった場所が順に残る。

```
WAIT=90 tool/device-screen.sh ios
```

**終わったら本来のエントリポイントを焼いて入れ直す。** バンドル ID は同じなので、
放置すると端末に残るのはプローブになる。

見た目の崩れに実機は要らない——**ゴールデンテスト**の領分。実機で見るのは OS が絡む挙動だけ。

## ストアに出す画は、シミュレータで撮る

```
make shots-ios       # 1320x2868（6.9 インチ）
make shots-ipad      # 2064x2752（13 インチ）
make shots-android   # 1080x1920（9:16）
```

3つとも `lib/shot_screen.dart` を焼く。**本物のアプリに、行を自分で入れただけのもの**である。
出るのは `store/screenshots/<枠>/` に4枚——前の画面・タスクの詳細・さがす・ペアリングの案内。

**iPad は予備ではない。** App Store は13インチの画が無い掲載を受け取らない。そして
**このアプリの広いときの形を見る場所は、ここしか無い**——一定の幅を超えるとタブは横のレールに移り、
開いたものは一覧の隣に立つので、タブレットにはスマートフォンが一度も描かない画面が出る。

- **詳細は押し込まず、シェルに開かせる**（`initialTask`）。ここで手前から `push` すると、
  タブレットの画に「そのアプリには無い形」が写る
- **シミュレータは英語にしてから撮る。** iPad は時計の隣に日付を書くので、そこだけが
  「19言語に1組」の画へ焼き込まれた別の言語になる

**実機では撮らない。** 理由は2つあって、どちらか片方でも十分になる。

- **ストアの枠は、端末の寸法ではない。** 手元の端末がその枠を持っているとはかぎらず、
  外れれば引き伸ばした画を出すことになる。シミュレータなら枠の側から選べる
- **入れれば端末のアプリを上書きし、その端末が持っている写しを空にする。** だから Android 側は
  **エミュレータの serial しか掴まない**——ケーブルに繋がっている端末は素通りする

**行はアプリが自分で入れる**（`lib/shot_backlog.dart`）。ペアリングの入口はカメラで QR を読む1本きりなので、
シミュレータには外から行を入れる道が無く、何をしても案内画面のままになる。
中身は作り物で、**本物のバックログは使わない**——2つのストアへ出る画に、誰かの実際の行は載せられない。

**撮るのはアプリではなく、外から。** シミュレータの画素はこの機械のものだが、画面は押せない。
だからアプリが4画面を順に出して止まり、「いま何が出ているか」をファイルに書く。スクリプトはそれを見て撮り、
消す——消えたら次の画面へ進む。待ち時間を両側で当てっこしない。

**文字も飾りも焼き込まない**ので、英語の1組で19言語ぶんを兼ねる。撮り直しが要るのは画面が変わったときだけ。

## Play が要る、横長の1枚

```
make feature-graphic
```

Google Play は **1024×500 の画**が無いと掲載情報を保存できず、**トラックを公開できない**。
出るのは `store/graphics/feature-graphic-1024x500.png` の1枚きり。

**これは撮るものではなく、描くもの。** 中身はマークと `Amenbo Viewer` だけで、アプリの画面は載せない
——横500ピクセルに縦長の画面を入れれば、そこに書いてある字はどれも読めなくなる。
**言葉も焼き込まない**ので、スクリーンショットと同じく19言語で同じ1枚を使う。

- **マークの座標は `tool/brand_mark.dart`**。アイコンと同じ数字を読んでいて、下地もアイコンと同じ生成り色
- **`flutter test` で走る**（`tool/gen_feature_graphic.dart`）。字を組める画布はエンジンの中にしか無く、
  端末もシミュレータも要らないので、テストが最も軽い入口になる。**描くことはゲートに入れない**
  ——走らせればリポジトリのファイルを書き換えるので。出来上がった1枚の寸法は
  `test/store_copy_test.dart` が見ている
- **書体は Flutter SDK が持つ Roboto**。Android が読むときの顔で、リポジトリは何も抱えない
- **透明を持たせない**（Play が断る）。Flutter の PNG は必ず alpha を書くので、画素だけ取り出して
  `tool/png.dart` で焼く
