# store — ストアの掲載文

App Store と Google Play へ出す文を、**言語ごとに1ファイル**で置く。リリースのときは、ここから
**写して貼るだけ**（登録そのものは配布の手が行う）。

言語コードはアプリの辞書と同じもので、19ある——`en` `ja` `zh-Hans` `zh-Hant` `ko` `es` `pt-BR` `fr`
`de` `it` `ru` `hi` `id` `vi` `th` `tr` `pl` `nl` `uk`。ストア側のロケール名は綴りが違うことがあるので
（Play の中国語は `zh-CN` / `zh-TW`、両ストアの英語は `en-US`）、貼る先は同じ言語のものを選ぶ。

## 欄と上限

見出し（`## name` など）が欄の名前で、**`test/store_copy_test.dart` がこの表のとおりに数えている**。
上限を1字でも超えるとストアは受け取らない。

| 見出し | 何の欄か | 上限 |
|---|---|---|
| `name` | アプリ名（両ストア） | 30 |
| `subtitle` | App Store のサブタイトル | 30 |
| `short` | Play の簡単な説明 | 80 |
| `keywords` | App Store のキーワード（カンマ区切り・Play に欄は無い） | 100 |
| `description` | 長い説明（両ストア） | 4000 |
| `release_notes` | リリースノート（App Store は 4000 だが、**Play が 500**） | 500 |

## 書き方

- **訳さない。** 同じことを、その言語で言う。上限の短い欄は語の長い言語で必ず溢れるので、
  収まる言い方に置き換える——縮めた結果として意味が痩せるくらいなら、別の言い方を選ぶ
- **アプリ名は19言語とも同じ**（`Amenbo Viewer`）。表示名は日英どちらでも通るので、言語ごとに変えない
- **長い説明は「PC 側の Amenbo が要る」から始める。** それが無ければ何も届かないアプリで、
  買ってから気づく話ではない
- 語は本体の辞書から引く（`nav.decisions` / `search.kind.task` などが、その言語で製品が使っている語）

## 画

`screenshots/ios/`・`screenshots/ipad/`・`screenshots/android/` に4枚ずつ。**英語の1組きり**で、
19言語とも同じものを貼る——画に文字を焼き込んでいないので、言語ごとに撮り直すものが無い。

**iPad の1組は必須**（2064×2752）。13インチの画が無いと、App Store は掲載を受け取らない。

撮り方と、なぜ実機で撮らないかは `../README.md`。画面を作り直したら撮り直す。

`graphics/` は画面ではない画。**Play が要る 1024×500 の横長の1枚**（`make -C app feature-graphic`）と、
**Play が並べる 512×512 のアイコン**（`dart run tool/gen_brand_assets.dart`——端末のアイコンと
同じ座標から焼く。手で描かない）。どちらも19言語で同じものを貼る。
**ストアへ送るのは `uv run app/tool/release/play.py graphics`**——焼き直しただけではストアは古いまま。
横長の1枚の**寸法と透明の有無は `test/store_copy_test.dart` が見ている**——欄の字数と同じで、
コンソールで断られてからでは遅い。
