WHAT THE APP IS, AND WHO IT IS FOR

Amenbo Viewer is the phone half of Amenbo, a local-first task manager that runs on the user's own computer (macOS, Windows or Linux). Amenbo keeps a backlog there — tasks, decision records and the comments on both. This app reads it on the phone, and never writes to it.

It is for people who already run Amenbo on their own machine — mostly developers who track work alongside AI coding agents — and want to read that backlog away from the desk. It otherwise lives on one computer and is reachable nowhere else.

WITHOUT A PAIRED COMPUTER, THE APP SHOWS ITS PAIRING GUIDE

There is no account, no login, no content of ours. The app has nothing to show until a computer hands it a backlog, so a reviewer without Amenbo installed sees the pairing guide and nothing else. That is the intended state, not a crash. "What is this app" and the privacy policy are both reachable from that guide, before any pairing.

HOW TO SEE IT WORKING

Attached is a pairing code (pairing-appreview.png), so you can walk the whole flow yourself: display it on any screen and point the app's camera at it. It pairs the app with a sample backlog we stood up for this review — invented rows about a website relaunch, on a Worker that holds nothing else. Nothing to type: the code carries the address, the read token and the key.

The app does not read codes out of the photo library, deliberately: the key would then sit there and in every backup it reaches. A code on a screen read by the camera is the only path, and it is the path a real user takes.

After scanning, the first sync runs and the app opens on the task list. The three tabs are tasks, decision records and search. The task screen switches between four states (to do, in progress, blocked, done). Tapping a row opens its detail and comments. Turn the network off and it all still reads: the phone works from its own copy.

HOW A REAL USER SETS IT UP

1. Install Amenbo on a computer, and its viewer plugin.
2. Deploy the viewer Worker into their own Cloudflare account. The plugin does it; what the user supplies is one API token, once.
3. Scan the code the computer displays.

What crosses the network is ciphertext. The key never travels over it, only optically in the QR code — that is why the camera is requested, and it is the only reason. There are no credentials to supply anywhere in this app.

New in this version: nothing about the route or the permissions changed. What moved is what the app says when the Worker answers 503. A Worker whose database has hit a daily limit of its own was being read as "your PC is still sending all your tasks", which pointed the user at the one end that has nothing to do with it. Those two are now told apart by the Retry-After header, and the limit has its own line in all nineteen languages: nothing is lost, nothing is damaged, and time is what ends it.

DEVICE MODELS AND OPERATING SYSTEMS TESTED

- iPhone 12 mini (iPhone13,1), iOS 26.6 — physical device, full pairing and sync flow
- iPhone 17 Pro Max simulator, iOS 26.5
- iPad Pro 13-inch (M5) simulator, iOS 26.5

Minimum supported version is iOS 15.0.

EXTERNAL SERVICES, TOOLS AND PLATFORMS

- Cloudflare Workers — deployed into and owned by the END USER's Cloudflare account. For a shipped app we operate no instance and hold no account on the user's behalf. The one exception is the sample Worker behind the code we sent, which exists for this review and holds only invented rows.

There is no analytics, advertising, crash reporting, authentication provider, payment processor or AI service. The app makes no network request other than to the Worker its pairing code names, so no data of any kind reaches us.

REGIONAL DIFFERENCES

None. The app behaves identically in every region. It is localized into 19 languages, but no feature or content differs by region. What is shown is whatever the user's computer wrote.
